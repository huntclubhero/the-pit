## SURVIVOR 1 (MEDIUM, conf HIGH): W2-1 residual via LIQUIDITY CONCENTRATION. The fix moved the lever, did not remove it.
Refs: UniV3TwapLib.consultMeanQuoteReserve (:126-174, virtual reserve :168-172); OracleRouter._poolQuoteAmount (:1077-1091), _trackedLiquidity (:1054-1067), costToMoveEstimate1e18 (:750-754), maxMarketPayoutCap1e18 (:767-771).
Fix does correctly: re-bases depth off balanceOf onto TIME-AVERAGED IN-RANGE quote reserve = meanL * f(sqrtP_meanTick), both time-averaged from the settlement TWAP's observation buffer. Defeats the PoC's two attacks: (a) single-sided OUT-OF-RANGE JIT inflates only balanceOf never in-range L (contributes 0); (b) single-block in-range spike earns one block of harmonic-mean weight. PoC passes; math confirmed.
Lever it OPENS: the new basis is the VIRTUAL in-range reserve = L*sqrtP (or L/sqrtP). For two-sided real quote Q concentrated in a thin band of half-width d, L ~ 2Q/(sqrtP*d), so virtual reserve ~ 2Q/d. At d=0.1%, ~$10k of real quote reports as ~$10M depth. OLD balanceOf: concentration REDUCED the reading; NEW: concentration INFLATES it ~1000x. Virtual in-range reserve measures LOCAL depth at the current tick; the cost-to-move cap (linear in depth) assumes depth extends across the move, but concentrated liquidity does not: cross the +/-0.1% band once (~$10-20k) and beyond it ~zero liquidity, so holding spot displaced across the TWAP window is free. Cap baked ~$2M (SF 5); true move cost ~$10k. Defeated ~200x.
Cost vs old: old = free flash loan; new = ~$10k of quote held in-range across the seasoning+window period; in the A1 single-pool no-external-arb scenario the band is never crossed by organic flow so the capital is NOT at risk, recovered post-snapshot: effective cost ~gas + brief opportunity. Harder than free, still cheap vs the unlocked cap.
Regression test misses it: JitSnapshotInflation.t.sol:168-175 sets meanL DIRECTLY on the mock at tick 0 (reserve==meanL); proves a balanceOf spike does not move a fixed meanL, never models achieving high meanL cheaply via a narrow range.
Refutation (survives): needs the token listed B_DEEP/C_MID (pool-priced, no independent feed) AND attacker-controlled pool flow = the standing A1 precondition. isListable enforces _hasIndependentSource only for A_MAJOR (:679,:721-731), NOT B_DEEP/C_MID, so A1 is still open in code for memecoins. Seasoning proves AGE not depth. Linear costToMoveCoeff cannot distinguish concentrated from spread at equal L.
BOTTOM LINE: latent for MAJORS-ONLY launch (no pool-priced markets); LIVE the moment any value-bearing pool-priced market is enabled. Fix must NOT be read as making the memecoin backstop safe. FOLLOW-UP FIX: either (i) do not enable B_DEEP/C_MID on the strength of this fix (chief P0 majors-only), or (ii) make cost-to-move concentration-aware: use actual balanceOf as an additional MIN alongside the virtual reserve, OR derive depth from liquidity across the +/-2% tick band the move actually spans, not the single in-range tick.

## SURVIVOR 2 (LOW, hardening): geometry window decoupled from settlement TWAP window
