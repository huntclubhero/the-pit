# Wave 3 Re-Audit: W2-2 jackpot drip
Auditor: re-jackpotdrip (Fable) | 2026-07-23 | Verdict: drip is SOUND for the DAILY draw and holds its EV claim, but ONE conditional survivor on the WEEKLY draw (backward epoch-attribution). Corroborates re-potguard's handoff.

## Q1: does the drip close the wash-farm?
DAILY: YES, closed. Re-derived with real constants: jackpot inflow = 25% of fees; max points amplifier A = winMult 5x x dailyMult 1.5x = 7.5x (maker-2x + spin bonus cancel in the point-SHARE ratio; L3 only slows the climb, table caps at 5x). Drip budget/epoch = 0.5 x 0.25 x epochFees = 0.125 x epochFees; break-even A=8. EV(F_a) = [A F_a/(A F_a + F_h)] x 0.125 x (F_h+F_a) - F_a with A=7.5 is strictly NEGATIVE for all F_a>0. Self-funding (25% share, 8x-lev) nets negative; donating (100% share, 2x-lev) recovers <=0.5x. seed() excluded (advances _accountedReceived past the deposit after pre-sync). Daily wash-farm non-positive-EV. Fix works.

## SURVIVOR (MEDIUM, conf HIGH mechanism / MED economics): weekly draw harvests CURRENT epoch honest inflow into a cheaply-dominated PREVIOUS epoch via backward lazy attribution
Root cause: inflow has NO time-of-arrival attribution. _syncInflow(epoch) (:667-676) dumps ALL unattributed deposits since the last sync into whatever epoch the caller NAMES. startDraw(WEEKLY) names target = currentEpoch-1 (PREVIOUS epoch): _syncInflow(target) at :489, fulfillment re-syncs to draw.epoch (same previous epoch) at :578. The weekly weights epoch E while currentEpoch = E+1, so any E+1 honest inflow still unattributed when the weekly triggers gets swept BACKWARD into epochInflow[E] and becomes payable to whoever dominates E's stale cheap points. The fix comment (:576-577) only guarded the FORWARD direction and over-corrected into a backward leak (worse: E is a completed epoch an attacker can have cheaply cornered). Decouples payout from the DEFENDING points, the exact invariant the drip enforces.
Worked (sole-keeper/unincentivized-draw norm): week E quiet, attacker spends ~$1k to hold q_E~0.9 of E's small point mass. Week E+1 gains traction: ~$200k fees -> ~$50k inflow during E+1. Attacker does NOT call daily draws/syncInflow in E+1, then at end of E+1 calls startDraw(WEEKLY) for E -> _syncInflow(E) sweeps ~$50k into epochInflow[E]. Weekly budget = 0.5 x $50k = $25k; pot>=$50k so fractionCap+outflow non-binding; drip pays q_E x $25k ~ $22.5k for ~$1k cost. Net ~+$21.5k = original H-J1 magnitude reconstituted on the weekly out of honest E+1 inflow. epochInflow[E] consumed, so E+1's own weekly is starved: theft from honest holders.
Self-refute (MEDIUM not HIGH): magnitude bounded by the largest unattributed-inflow gap at the attacker's weekly trigger. Any honest syncInflow() or startDraw(DAILY) (both attribute to CURRENT epoch) shrinks the gap; a keeper syncing hourly caps harvest at ~1h of inflow (~break-even after the $1k cost). An honest startDraw(WEEKLY) for E early in E+1 forfeits the harvest entirely. Real + code-confirmed but conditional on the attacker being de-facto draw-caller + winning the attribution race; rises to HIGH under thin keeper coverage, fully defused by a keeper syncing at rollover + prompt weekly.
FIX: finalize/snapshot each epoch's inflow at the boundary (attribute by arrival; carry an `unattributed` bucket that closes when currentEpoch advances) so the weekly budget only includes inflow that genuinely arrived during epoch E; and/or auto-sync-to-current on any rollover interaction; and/or incentivize prompt weekly triggering.

## Q2: new bugs? mostly SOLID
(a) Lazy accounting integrity SOLID: cumulativeReceived = balanceOf + cumulativePaidOut strictly monotonic (claim decrements balance + increments paidOut equally; credits move no tokens; donations/fees/seed only raise it); _accountedReceived only advances, never re-attributes; claim is the only token outflow and is tracked. No desync.
(b) totalClaimable <= balance HOLDS (amount <= fractionCap <= pot; claim decrements both; potBalance no underflow).
(c) seed() permissionless but SAFE (donates excluded funds, cannot steer; pre-syncs prior inflow before excluding its deposit).
(d) cancelStuckDraw/roll-forward/D2 CLEAN (cancel moves no funds, leaves epochInflow/epochPaidOut untouched; D2 pull-payment preserved, updates cumulativePaidOut).
LOW/info (no profit): startDraw(WEEKLY) for a 0-point epoch runs _syncInflow(target) before the skip (:489-492), stranding that inflow in a never-drawn bucket (stays in pot, permanently unpayable); combined with the by-design 50%-rolls-forward, the standing-pot headline increasingly diverges from the payable budget. Cosmetic/UX, not a drain.

Net: genuine correct fix for the DAILY wash-farm + direct self-funding vectors, but the WEEKLY backward epoch-attribution conditionally re-opens the wash-farm against honest current-epoch inflow. Close the attribution seam before relying on the drip as the P1 mitigation.
