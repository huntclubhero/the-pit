## SURVIVOR 1 (MEDIUM, HIGH conf): ADL haircut silently WASTED when the opposite-side victim is over its payout cap due to a FUNDING CREDIT. Composes FUNDING x PAYOUT-CAP CLAMP x ADL absorption accounting.

Root: _adl assumes shaving `haircut` off a victim's PnL reduces vault outflow by `haircut`, so it decrements uncovered bad-debt `remaining` by that nominal amount. But the victim's payout is INDEPENDENTLY clamped to maxPayout (:1483). When the victim holds a net funding CREDIT (fund<0), raw ask = priceWin + |fund| - bor can already exceed maxPayout, so the clamp is ALREADY binding at haircut=0. Marginal saving from haircut h is ZERO for all h up to (|fund|-bor): winFromVault stays pinned at maxPayout. ADL reports absorbing `haircut` while vault outflow does not move.
Reachability (all real states, test_5c pushed harder): Alice long majority takes bad debt on a drop; Bob short minority RECEIVES funding + clamped price PnL at his 9x cap. Keeper liquidates Alice, IF empty, _adl(badWasLong=true) targets Bob; if shortfall <= (|fundB|-borB), haircut=shortfall, remaining=0, STOP; BadDebt emits adlAbsorbed=shortfall but Bob paid the identical pot. Result: (1) bad debt ADL promises to socialize is silently eaten by LPs; Bob overpaid by the wasted haircut. (2) early termination skips other absorbable victims. (3) BadDebt.adlAbsorbed overstated -> off-chain solvency monitor misled. Conservation still holds to the wei (single-feature attackers miss it; same class as the 2 integration seam bugs = one contract assuming linearity another clamps).
FIX: measure absorption from ACTUAL vault delta -> haircutEffective = winFromVault(0) - winFromVault(haircut); decrement `remaining` by that. A victim already at cap (winFromVault_raw >= maxPayout at haircut 0) is NON-absorbing; skip it and move to the next victim.
